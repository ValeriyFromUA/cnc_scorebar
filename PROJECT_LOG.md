# Project Log — Scorebar

Нотатки для Claude: особливості проєкту, важливі рішення дизайну та лог сесій.
Читати на початку роботи над проєктом, оновлювати по ходу і в кінці сесії.

## Огляд

Оверлей рахунку для CnC Generals: Zero Hour (PyQt6, Windows + macOS).
Точка входу: `control_panel.py` (`main()`), не `scorebar.py` — той лише
визначає `ScorebarWindow`, який імпортується з панелі керування.

Файли: `control_panel.py` (UI керування), `scorebar.py` (оверлей),
`data.py` (фракції/країни/моделі), `themes.py` (11 тем), `resources.py`
(шляхи до asset'ів, сумісні з PyInstaller onefile).

## Важливі рішення дизайну (не міняти не подумавши)

- **Числові поля в панелі керування (рахунок, розмір команди, к-сть FFA)
  навмисно без прямого вводу з клавіатури** — лише кнопки/стрілки спінбокса
  (`_button_only_spin`). Причина: оверлей і панель принципово не повинні
  перехоплювати клавіатуру гри. ELO — виняток, це `QLineEdit` з
  `QIntValidator`, не спінбокс.
- **Прапори країн — PNG, не emoji**: Windows з 2021 малює емодзі-прапор як
  дві літери коду країни замість іконки.
- **Оверлей — звичайне безрамкове вікно з заголовком "Scorebar Overlay"**,
  без `Qt.WindowType.Tool` — інакше OBS Window Capture його не бачить у
  списку джерел (WS_EX_TOOLWINDOW на Windows).
- **"Завжди зверху" вимкнено за замовчуванням** — OBS сам компонує джерело
  в сцену незалежно від порядку вікон; topmost потрібен лише для перегляду
  поза OBS.
- **Конфіг лежить поруч з exe**, не в robочій теці ярлика; фолбек —
  `%APPDATA%\Scorebar` (Windows) / `~/.config/scorebar`, якщо тека
  тільки для читання.
- **Вкладка "Сумісність"**: суцільний фон (чорний/хромакей) + маска вікна
  за формою скорбару — для старих capture-методів (BitBlt), які не
  знімають напівпрозорі вікна.
- Іконки фракцій/генералів — реальні асети гри (`Icons/Generals`,
  `Icons/Armies`), 3 кольорові варіанти (blue/orng/slvr), спільні на весь
  скорбар. Розмір бейджа зараз **захардкоджений** `setFixedSize(38, 38)`
  в `FactionBadge` (scorebar.py:401).
- ELO гравця: `Player.elo: int | None`. Якщо `None` — на скорбарі просто
  порожній рядок (scorebar.py:664). Ручне поле в `PlayerEditRow` при
  очищенні падає назад на значення з сайту (`self._elo`), а не на `None`
  — тому зараз немає способу примусово прибрати ELO, якщо гравця обрано
  зі списку сайту (це один із запитів користувачів, див. нижче).
- Фракція/генерал — завжди обов'язкові, дефолт `"usa"`
  (`combo_get_data(self.faction_combo) or "usa"`, control_panel.py:371).
  Пустого варіанта в комбобоксі немає.
- Показ/приховування елементів — є вже готовий патерн: `show_title_check`
  (checkbox в дизайн-вкладці) → `set_title_visible()`. Той самий підхід
  варто повторити для майбутніх "показувати рахунок / генерала / ELO".

## Лог сесій

### 2026-09-17
- Розібрав структуру проєкту й README для користувача.
- Користувач попросив вести цей лог з моменту сесії.
- Зібрано список побажань користувачів і всі 6 реалізовано:
  1. **Ручний ввід чисел скрізь** (рахунок, розмір команди, к-сть FFA,
     шрифти/відступи/розмір іконок) — `_button_only_spin` перейменовано на
     `_configure_spin` (control_panel.py), прибрано `setReadOnly`/
     `FocusPolicy.NoFocus`. Стрілки/кнопки +/- лишились поруч. Перевірено:
     оверлей (`ScorebarWindow`) ніколи не приймає фокус
     (`WA_ShowWithoutActivating` + `FocusPolicy.NoFocus`), тож клавіатурний
     фокус у панелі керування нічого не "перехоплює" — старий страх був
     необґрунтований для поточної версії коду.
  2. **Розмір іконок генералів у px** — новий стан `icon_size` прокинутий
     через увесь ланцюжок `FactionBadge → PlayerRow → TeamPanel/FFAPanel →
     ScorebarWindow.set_icon_size()`; степер "Розмір іконки, px:" (24–64,
     дефолт 38) у вкладці Дизайн, поруч з вибором кольору іконки.
  3. **Нові країни**: Іран, Палестина, Сирія (пост-2024 прапор — зелений/
     білий/чорний з трьома зірками, а не старий баасистський), Ліван —
     додані в `data.py`. Прапори PNG згенеровано скриптом (Pillow) у тому ж
     форматі, що й наявні (80px по ширині, реальні пропорції), лежать у
     `Icons/Flags/{ir,ps,sy,lb}.png`. Ліванський кедр перемальовував двічі —
     з першого разу вийшов невиразний зелений блоб.
  4. **Прибрати ELO**: чекбокс "Без ELO" в кожному рядку гравця
     (`PlayerEditRow.hide_elo_check`, форсує `elo=None` в `to_player()`
     незалежно від значення з сайту) + глобальний чекбокс "Показувати ELO"
     у вкладці Дизайн (`ScorebarWindow.set_elo_visible`, ховає
     `rating_label` в усіх рядках одразу).
  5. **Без генерала** — новий пункт "— Без генерала —" в комбобоксі
     фракції, сентинел `NO_FACTION_KEY = "none"` в `data.py` (окремий від
     "" — того значення, яке `combo_get_data` повертає при помилці
     читання комбобокса, щоб не сплутати навмисну відсутність з багом).
     `get_faction()` повертає `None`, `FactionBadge`/`set_faction` це
     приймають і нічого не малюють.
  6. **Прибрати рахунок** — чекбокс "Показувати рахунок" у вкладці Дизайн
     (`ScorebarWindow.set_score_visible`): ховає `CenterScorePanel` у
     командному режимі і особистий рахунок у рядках FFA (сортування по
     рахунку в даних не зачіпається, ховається лише відображення).
- Усі нові прапорці збережено/відновлюються через `_build_config_dict`/
  `_apply_config_dict` (`icon_size`, `show_elo`, `show_score`).
- **Фідбек користувача під час тестування**: чекбокс "Без ELO" спершу був
  без підпису (лише тултіп) — незрозуміло, що це. Виправлено, тепер має
  видимий текст "Без ELO" на самому чекбоксі.
- Перевірено наживо (запуск `control_panel.py` через venv): ручний ввід
  працює (видно курсор у полі "Розмір команди"), ELO рендериться на
  оверлеї, чекбокс "Без ELO" тепер підписаний.
- **Нюанс з тестуванням**: під час live-перевірки один раз побачив
  "Показувати ELO" не позначеним попри дефолт `True` в коді — після
  чистого перезапуску (без жодної взаємодії) й повторної активації вікна
  через `osascript` це не відтворилось двічі поспіль, тож найімовірніше
  це був артефакт зомбі-процесу від невдалого першого фонового запуску (з
  `&` замість `run_in_background`), а не баг у логіці. Якщо це
  повториться в майбутньому — варто перевірити ще раз уважніше.
- Тестування живого застосунку автосейвило `scorebar_config.json`
  (git-ignored, реальні дані користувача — матч "Holton" vs "Ing.
  Vladyslav Kostiuk", "UA CUP 2020") кілька разів; основні поля (рахунок,
  назви, тема, шрифти) лишились цілими, додались лише нові ключі.
  6. Можливість не вказувати рахунок взагалі (сховати з оверлею).
